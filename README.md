# SmartGate MVP

منصة هاكاثون لتنظيم **دخول** الشاحنات: تخطيط الرحلة، QR، التوصيات، التحقق، طلب فتح الحاجز، نتيجة الفتح، ثم تأكيد العبور والتقرير والإشعارات. الخروج والعمليات داخل الميناء خارج النطاق.

الحسابات والحفظ والصلاحيات تعمل فعليًا في Supabase. الازدحام والكاميرات والحاجز والعبور **محاكاة معلنة**، وليست تكاملًا ميدانيًا.

المنصة المنشورة: [SmartGate](https://smartgate-gold.vercel.app/ar/login). بعد الدخول، افتح «سيناريوهات العرض» لتجربة الحالات الـ13.

## التشغيل المحلي

يتطلب Node.js 24 وnpm، ومشروع Supabase تطبق عليه الترحيلات.

~~~sh
npm ci
~~~

انسخ `.env.example` إلى `.env.local` واضبط عنوان المشروع ومفتاحه العام. لا يحتاج التطبيق مفتاح service role.

~~~sh
npm run dev
~~~

افتح http://localhost:3000/ar/login. ولتشغيل البناء النهائي:

~~~sh
npm run build
npm start
~~~

`/api/health/supabase` يفحص اتصال Auth دون كشف مفاتيح أو بيانات مستخدمين.

## التحقق

~~~sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
~~~

- Vitest: منطق التقدير والتحقق واللغة، واختبارات PostgreSQL/RLS بواسطة PGlite. لا تحتاج Docker؛ يُحقن سياق JWT في بيئة الاختبار المعزولة فقط.
- Playwright: حسابات حقيقية على Supabase وواجهة بناء الإنتاج؛ يبدأ `npm start` تلقائيًا إذا لم توجد خدمة محلية. يتطلب `.local/demo-accounts.json` أو `E2E_ACCOUNTS_JSON`.
- للتحقق من نشر معين، اضبط `E2E_BASE_URL`. الاختبارات تنشئ رحلات عرض وتعيد ضبطها عبر RPC المخول؛ تحفظ نسخة تدقيق لإعادة الضبط. اختبارات السيناريو تعدل البوابات التجريبية، فلا تشغلها أثناء عرض حي.
- للمعاينة المحمية، نفذ `vercel env pull .local/verification.env --yes` ثم اضبط `E2E_AUTH_ENV=.local/verification.env`. يستخدم الاختبار رمز OIDC قصير الأجل للنطاق المحدد فقط؛ لا تطبع الملف أو تشاركه. اعتمادات قديمة في `.env.local` قد تكون منتهية.
- GitHub Actions يشغّل lint وtypecheck وVitest والبناء. اختبارات المتصفح السحابية تُشغّل محليًا بالحسابات الخاصة، وليست مشروطة بأسرار مخزنة في المستودع.

## ما نُفّذ

| المجال | السلوك |
|---|---|
| الحسابات | شركة، سائق، مشغل بوابة، مسؤول محاكاة؛ حسابات مجهزة دون تسجيل عام |
| العزل | RLS وعمليات قاعدة بيانات تتحقق من الهوية والدور والشركة والسائق والبوابة |
| الرحلات | إنشاء وتحقق من البيانات، رقم طلب مقروء، QR، تفاصيل وسجل متصل |
| التقدير | الطابور × 60 ÷ معدل الخدمة؛ البيانات المفقودة لا تُعامل كصفر |
| التوصيات | بديل مفتوح ومؤهل ضمن الموعد؛ حفظ الاقتراح والسبب والوقت قبل القبول |
| الدخول | تحقق ثم طلب فتح ثم نتيجة حاجز ثم عبور مستقل؛ الفتح وحده لا يكمل الدخول |
| الاستثناءات | عدم التطابق، فشل الحاجز وتصعيده، انتظار العبور، فشل إشعار |
| التقارير | سجل الرحلة والبوابات والتوصيات والقراءات والأعطال والعبور وحالتا إشعاري الإكمال |
| المحاكاة | تعديل البوابات وقراءات الأجهزة، وإعادة ضبط رحلة عرض مع حفظ سجل تدقيق |
| الواجهة | هوية SmartGate الأصلية، عربية/إنجليزية، هاتف/تابلت/حاسوب، حالات تحميل وفراغ وخطأ |

تشمل النسخة مكتبة من 13 سيناريو محفوظًا وقوالب لتجارب جديدة، وبحثًا وتصفية وصفحات للقوائم، وطباعة التقارير أو حفظها PDF من المتصفح. لا تشمل خرائط/GPS أو مسح QR بالكاميرا أو تصدير CSV أو SMS/WhatsApp/بريد أو تكامل أجهزة. تستخدم تحديث الحالة اليدوي بين الحسابات؛ التشغيل دون اتصال غير مدعوم.

## قاعدة البيانات

الترحيلات في `supabase/migrations/` وأنواعها المولدة في `src/types/database.ts`. لا تكتب الجداول المحمية مباشرة من العميل؛ تستخدم Server Actions عمليات RPC ذرية مع مفاتيح لمنع تكرار الطلب. إعادة تأكيد العبور لا تنشئ دخولًا أو إشعارات مكررة.

[دليل التجربة](docs/DEMO-GUIDE.md#تجهيز-بيئة-جديدة) يشرح تجهيز الحسابات بالسكربت الإداري `scripts/provision-demo.sql`. لا يعاد توليد كلمات المرور أو حذف الحسابات عند إعادة تشغيله؛ يرفض التكرار.

## النشر والأمان
