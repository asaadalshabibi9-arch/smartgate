# دليل تجربة SmartGate MVP

الحسابات والبيانات محفوظة فعليًا في Supabase. البوابات والازدحام وقراءات الهوية والحاجز والعبور كلها **محاكاة معلنة**؛ لا تصاريح رسمية ولا اتصال بميناء.

## الدخول والأدوار

افتح النسخة العربية `/ar/login` أو الإنجليزية `/en/login`. بيانات الدخول في الملف المحلي الخاص `.local/demo-accounts.md`، المستثنى من Git والنشر. لا توجد شاشة تسجيل عام.

رابط المنصة المنشورة: https://smartgate-gold.vercel.app/ar/login . لا تحتاج حساب Vercel؛ استخدم حساب SmartGate المجهز لك. صفحة السيناريوهات بعد الدخول: `/ar/scenarios`، والنسخة الإنجليزية: `/en/login`.

استخدم ملفات متصفح أو نوافذ خاصة **مستقلة** لكل حساب؛ علامات التبويب في النافذة نفسها تتشارك الجلسة.

| مفتاح الحساب | الاستخدام |
|---|---|
| company | إنشاء رحلات شركة المسار ومتابعتها وتقاريرها |
| driver | السائق سالم: بدء رحلاته وقبول التوصية وتسجيل الوصول |
| operator | مشغل GATE-A وGATE-B: طلب فتح الحاجز بعد نجاح التحقق |
| simulation | تعديل سيناريو البوابات وقراءات التحقق ونتائج الحاجز وتأكيد العبور |
| driver2 | سائق ثانٍ في الشركة نفسها، لإثبات عزل رحلات السائقين |
| company2 / driver3 | شركة ثانية وسائقها، لإثبات عزل الشركات |
| operator2 | مشغل GATE-C فقط، لإثبات عزل البوابات |

## سيناريو كامل

يوجد الآن قسم **«سيناريوهات العرض»** في القائمة، ويضم 13 حالة مع خطوات الأدوار والنتيجة المتوقعة. يربط القسم بالرحلات المحفوظة المسموح لحسابك رؤيتها. يستطيع حساب الشركة اختيار «إنشاء تجربة جديدة» للحصول على نموذج معد مسبقًا؛ يلزم اختيار السائق والشاحنة والبوابة ثم تنفيذ الخطوات من حساب كل دور. سيناريو الشركة الثانية مخصص لإثبات العزل ولا ينشئه قالب الشركة الأولى.

يمكن البحث في سجل الرحلات برقم الطلب أو الحاوية أو وصف الحمولة أو اسم السيناريو، وتصفية الحالة والمعاملة. تعرض القوائم عشر رحلات في الصفحة. قائمة التقارير تفتح التقرير مباشرة؛ زر «طباعة التقرير» يهيئ نسخة للطباعة أو الحفظ PDF من المتصفح، مع وسم المحاكاة.

1. **الشركة:** «إنشاء رحلة»، اختر سالم وشاحنة `DEMO-1001` و`GATE-A`. أدخل وصف الحمولة والوزن ورقم الحاوية. الأوقات بتوقيت مسقط؛ اترك نافذة الموعد الحالية للتجربة أو اختر نافذة تشمل وقت التجربة ومدة السفر. احفظ الطلب وافتح تفاصيله؛ يظهر QR ومعرّف الرحلة.
2. **السائق:** افتح الرحلة ثم «بدء الرحلة». عند وجود بديل أقل انتظارًا اضغط «قبول التوصية». الاقتراح والسبب والقبول محفوظة في السجل؛ يعاد فحص الشروط عند القبول. بعدها «تسجيل الوصول».
3. **المحاكاة:** افتح الرحلة. حقول QR واللوحة والحاوية تمثل قراءات محاكاة، وتعبأ بالقيم المطابقة لتسهيل العرض. «محاكاة قراءة الهوية والتحقق» يسجل نتائج المطابقة مستقلة.
4. **المشغل:** حدّث الحالة، ثم «طلب فتح الحاجز». هذا طلب فقط؛ لا يسجل فتحًا أو دخولًا.
5. **المحاكاة:** حدّث الحالة ثم «محاكاة نجاح الفتح». يبقى الطلب في «انتظار تأكيد العبور» ولا يظهر دخول مكتمل.
6. **المحاكاة:** «تأكيد عبور محاكى». عندها فقط تثبت أوقات العبور والإكمال وتتاح إشعارات الشركة والسائق.
7. **الشركة والسائق:** افتح «تقرير الدخول» والإشعارات. التقرير يتضمن الهوية والبوابات والتوصيات والقراءات والأعطال ووقت العبور وحالتي إشعاري الإكمال.

تتحدث الحالة عبر Realtime، مع تحديث احتياطي كل 20 ثانية أثناء ظهور الصفحة واتصالها؛ زر «تحديث الحالة» متاح أيضًا. فُعّلت الإدارة بحساب مستقل ونجح تجهيز حسابات من الواجهة. افتح `.local/platform-admin-access.md` للحصول على بيانات المدير ثم `/ar/administration`. رسالة Resend التجريبية وصلت إلى صاحب الحساب؛ إشعارات الرحلات الخارجية لم تُفعّل لغياب نطاق موثق. [دليل تفعيل التوسعة](EXPANSION-SETUP.md) يشرح اللغات الثماني والكاميرا والخرائط والإدارة والربط المتبقي.

## سيناريوهات الفشل

- **هوية غير مطابقة:** غيّر اللوحة أو QR أو الحاوية قبل التحقق. يسجل الاستثناء ولا يتاح طلب الفتح؛ صحح القراءة وأعد التحقق.
- **عطل الحاجز:** بعد طلب المشغل، اختر «محاكاة فشل الفتح». يظهر عطل وتصعيد للمشغل دون إكمال. أعد طلب الفتح من المشغل ثم اختر النتيجة من المحاكاة.
- **عدم وجود عبور:** افتح الحاجز واتركه دون تأكيد العبور؛ تظل الرحلة غير مكتملة مهما تكرر تحديث الشاشة.
- **غياب بيانات التقدير:** من المحاكاة افتح «تحديث السيناريو» لبوابة وامسح الطابور أو معدل الخدمة. لا تتحول القيمة المفقودة إلى صفر. لإعادة السيناريو: A مزدحمة بطابور 8 ومعدل 15، B متاحة بطابور 3 ومعدل 15، C مغلقة دون بيانات.
- **إغلاق بديل:** أغلق B؛ لا يوصى بها. يجب أن تشمل نافذة الموعد وقت الوصول التقديري حتى تقدم توصية صالحة.
- **فشل إشعار:** بعد الإكمال، مسؤول المحاكاة يستطيع تسجيل فشل إشعار طرف محدد؛ تبقى الرحلة مكتملة ويظهر الفشل في التقرير.
- **انقطاع الاتصال:** لا تفترض حفظ الإجراء عند فقد الاستجابة. أعد الاتصال وحدّث الحالة قبل المحاولة؛ أوامر الرحلة محمية من تكرار نفس الطلب، والإكمال محمي أيضًا من إشارات عبور متكررة.

## بيانات العرض وإعادة الضبط

`node --env-file=.env.local scripts/seed-showcase.mjs` يجهز أربع رحلات اصطناعية مختلفة عند عدم وجود مجموعة عرض محفوظة سابقًا، ويستخدم صلاحيات الحسابات نفسها. لا يمسح رحلات المستخدم. مواعيد رحلات العرض صالحة 24 ساعة من تجهيزها؛ أنشئ رحلة جديدة للعرض في يوم آخر.

من تفاصيل الرحلة، يستطيع مسؤول المحاكاة فتح «إعادة ضبط هذه الرحلة التجريبية» وتحديد مربع التأكيد. يحذف ذلك رحلة العرض المحددة وتوابعها، ويحفظ نسخة كاملة في سجل إعادة ضبط خاص بالمشرف. لا يتاح هذا الإجراء للسائق أو الشركة أو المشغل.

## تجهيز بيئة جديدة

لإضافة حزمة السيناريوهات بعد تجهيز الحسابات، نفّذ `node --env-file=.env.local scripts/seed-scenarios.mjs` ثم `node --env-file=.env.local scripts/verify-scenarios.mjs`. الإضافة تحفظ الرحلات السابقة وتتجاوز الحالات الموجودة دون إعادة ضبطها. تُحفظ مراجع الحالات في `.local/scenarios.json`، ونتائج التحقق في `.local/scenario-verification.json`، دون كلمات مرور.

| الرمز | الحالة الجاهزة |
|---|---|
| SC01 | دخول سليم مكتمل |
| SC02 | قبول تغيير البوابة ثم دخول مكتمل |
| SC03–SC05 | اختلاف اللوحة، ثم QR، ثم الحاوية كحالات مستقلة |
| SC06 | عطل حاجز مع تصعيد |
| SC07 | فتح مع انتظار العبور، دون إكمال |
| SC08–SC09 | موعد منتهٍ ووصول مبكر |
| SC10 | بيانات ازدحام غير متاحة |
| SC11 | بضائع عامة مكتملة مع فشل إشعار السائق |
| SC12 | تعافٍ بعد فشل الحاجز مرتين |
| SC13 | رحلة لشركة أخرى لإثبات حدود الاطلاع |

1. انسخ `.env.example` إلى `.env.local` واضبط عنوان Supabase والمفتاح العام؛ لا يحتاج تشغيل التطبيق مفتاح service role.
2. طبق ملفات `supabase/migrations/` بالترتيب على المشروع المقصود، ثم `supabase/seed.sql` للبوابات.
3. نفّذ `scripts/provision-demo.sql` بصلاحية مدير قاعدة البيانات. يولد كلمات مرور عشوائية ويعيدها مرة واحدة؛ احفظ النتيجة محليًا، ولا تلصقها في Git أو سجل عام. يرفض التكرار إذا كانت حسابات العرض موجودة.
4. صيغة `.local/demo-accounts.json` مصفوفة تحتوي `account_key,email,password,profile_id,company_id`. تستخدمها أدوات التحقق وتجهيز العرض فقط؛ لا ترسلها إلى العميل أو Vercel.

حارس قاعدة البيانات يمنع التسجيل العام. بموجب A14، تتيح واجهة الإدارة إنشاء حسابات مجهزة عبر Auth Admin بعد حجز خاص موثق يطابق البريد ومعرف الحساب؛ لا يسمح بدور أو شركة يختارهما مستخدم عادي. يبقى سكربت التجهيز مرجعًا للتهيئة الأولى فقط، ولا تُمنح إدارة المنصة تلقائيًا لحساب المحاكاة. إضافة تسجيل عام ما زالت خارج القرار المعتمد.
